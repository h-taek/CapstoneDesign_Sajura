# Sajura 프로젝트 개발 규칙 (Team Conventions)

사주라(Sajura) 프로젝트를 진행하면서 모든 팀원이 반드시 지켜야 할 기본 개발 규칙입니다.

---

## 1. 환경 변수 (.env) 보안 규칙 
* **절대 `.env` 파일을 GitHub에 커밋하거나 공유하지 마세요.** (현재 `.gitignore`에 등록되어 있어 자동으로 무시되지만, 강제로 추가하지 않도록 주의합니다.)
* 데이터베이스 비밀번호, API 키 등 민감한 정보는 무조건 `.env` 파일에 작성하고 코드 내부에는 절대 하드코딩하지 않습니다.
* **`.env.example` 관리:** 프로젝트에 새로운 환경 변수가 추가되었다면, 반드시 `.env.example` 파일에도 해당 변수명(값은 비워두거나 예시로 작성)을 추가하여 커밋해야 합니다. 그래야 다른 팀원들이 pull을 받았을 때 어떤 변수를 새로 추가해야 하는지 알 수 있습니다.

## 2. 파이썬 가상환경 (venv) 및 패키지 규칙 
* **로컬(글로벌) 환경에 패키지를 직접 설치하지 마세요.**
* 개발을 진행할 때는 항상 가상환경(`.venv`)을 생성하고 **활성화(activate)** 한 상태에서만 진행해야 합니다.
* 가상환경 폴더 자체(`.venv/`)는 무거우며 환경마다 다르므로 GitHub에 절대 커밋하지 않습니다.
* **패키지 동기화:** 새로운 파이썬 라이브러리를 설치(`pip install`)했다면, 반드시 `pip freeze > requirements.txt` 명령어를 실행하여 변경사항을 기록하고 `requirements.txt` 파일을 커밋해 주세요.

## 3. 데이터베이스 및 Docker 규칙 
* 개별적으로 MySQL을 로컬 PC에 직접 설치하여 쓰지 말고, 제공된 **Docker Compose**(`Back/Docker/DB/docker-compose.yml`)를 사용하여 팀원 전체가 완벽히 동일한 DB 환경을 유지합니다.
* 컨테이너 초기화 스크립트(`init.sh`)나 `Dockerfile`을 수정했다면 팀원들에게 공유하고, 다 함께 `docker-compose up -d --build` 로 다시 빌드하여 환경을 맞춰야 합니다.

## 4. 버전 관리 (Git) 기본 규칙 
* 소스코드 실행 과정에서 생성되는 캐시 파일(예: `__pycache__`), OS 임시 파일(예: `.DS_Store`), IDE 설정 파일(예: `.vscode/`) 등은 커밋하지 않습니다.
* 의도치 않은 파일이 `git status`에 뜬다면 커밋하기 전에 반드시 `.gitignore`에 먼저 등록하세요.
