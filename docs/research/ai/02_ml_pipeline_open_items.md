## 2. 학습 데이터 사용 방식 — 미정 (슬라이딩 윈도우 적용 여부 포함)

> spec(`ml_pipeline.md` §2, `model_spec.md` §7)에 "슬라이딩 윈도우 방식 / 최근 N개월" 표현이 있었으나, 방식 자체가 확정 안 됨. spec에서 관련 내용 모두 제거하고 본 §2에서 후보 비교 후 역반영.

### 2.1 학습 데이터 사용 방식 후보

| 방식 | 설명 |
|---|---|
| 슬라이딩 윈도우(N개월) | 항상 최근 N개월만 학습, 그 이전 데이터는 자동 제외 |
| 전체 데이터 누적 학습 | 모든 과거 데이터 동일 가중치로 사용 |
| 시간 가중치 부여 학습 | 모든 데이터 사용하되 최근 데이터에 큰 가중치 (exponential decay 등) |
| 시즌별 분할 학습 | 시즌·요일 등 패턴별로 모델 분리 |

### 2.2 슬라이딩 윈도우 선택 시 N 값 후보

- 매장 운영 특성상 의미 있는 학습 구간(3·6·12개월) 비교
- 계절성 반영을 위한 최소 윈도우 길이
- 점주 메뉴 변경·매장 리뉴얼 등 도메인 변화 대응 방식

### 2.0 Walk-forward CV와의 관계 (참고)

학습 데이터 사용 방식(§2.1~2.2)과 CV 분리 방식(`01_model_selection.md` §3.1)은 연결된 결정이다:
- Walk-forward CV = 슬라이딩 윈도우를 CV fold 단위로 적용하는 것과 동일
- 계절성 반영을 위한 최소 윈도우: 52주(1년) 이상 권장 → 실 데이터 확보량에 따라 조정
- N 값(3·6·12개월)은 AutoGluon probe 시 walk-forward로 비교하여 결정

### 2.3 probe 후 spec 역반영 대상

- `ml_pipeline.md` §2 실행 방식
- `model_spec.md` §7 학습 방식

## 3. 결측·이상치 처리 기준 — 상세 정의 필요

> spec(`ml_pipeline.md` §6, `feature_spec.md` §4.6 등)에는 "이상치/결측값을 탐지·처리한다"는 사실만 남기고, 탐지 방법·임계값·처리 정책은 본 §3에서 확정 후 spec에 역반영한다.

### 3.1 결측값 보간 방법 ✅ 전략 확정 (컬럼별 적용은 probe 후)

> 근거: `00_ml_guide_reference.md` PART 1-0-6 결측치 처리 + PART 5-1 데이터 누수 방지

**시계열 특성 고려한 컬럼별 전략**:

| 컬럼 유형 | 권장 방법 | 이유 |
|---|---|---|
| 판매량 | forward-fill (ffill) 또는 같은 요일 평균 | 시계열 연속성 보존, 요일 패턴 반영 |
| 날씨·기온 | 선형 보간 (interpolation) | 연속 측정값, 인접값 기반 추정 타당 |
| 유동인구 | forward-fill 또는 같은 요일 평균 | 판매량과 동일한 주기성 |
| 공휴일·이벤트 | 0 채움 | 없으면 0 (이진 변수) |

**결측 비율 분기 기준 (잠정)**:
- 결측 비율 30% 미만: 위 전략대로 보간
- 결측 비율 30% 이상: 해당 기간 전체 학습 제외 고려 → probe 후 임계값 확정

**누수 방지 필수**: 보간에 사용하는 통계(평균 등)는 train fold에서만 계산, test에 적용. scikit-learn `Pipeline` 내부에서 처리 (PART 5-1).

### 3.2 이상치 탐지 방법 ✅ 방법론 확정 (임계 계수는 probe 후)

> 근거: `00_ml_guide_reference.md` PART 1-0-6 이상치 처리 + 회귀_분석.pdf "MSE는 이상치에 민감"

**권장: IQR 우선, Z-score 보조**

| 방법 | 적용 조건 | 이유 |
|---|---|---|
| **IQR** | 판매량 등 왜도 높은 분포 (histogram 치우침) | 정규분포 가정 불필요, 이상치에 강건 |
| **Z-score** | 날씨·기온 등 정규분포에 가까운 컬럼 | EDA에서 정규성 확인 후 적용 |

**결정 순서**: EDA에서 컬럼별 히스토그램·상자그림 확인 → 분포 형태에 따라 컬럼별 방법 지정.

**임계 계수**: IQR × 1.5(일반) vs × 3.0(보수적) — 실 데이터 분포 확인 후 결정. 잠정 1.5 사용.

> 회귀 모델은 MSE 손실함수 사용 시 이상치에 민감하므로 이상치 처리가 예측 성능에 직접 영향.

### 3.3 이상 데이터 처리 정책 (spec에서 이동한 잠정값)

> 아래는 spec에서 "확정"으로 적혀 있던 잠정 정책을 옮긴 것. AI probe 후 정량 기준이 검증되면 spec에 역반영.

- **잠정 처리 분기**:
  - 이상치 비율 5% 미만 → 자동 분리, 알림 없음
  - 이상치 비율 5% 이상 → 점주 알림, 복구/폐기 선택
- **잠정 분리 정책**: 이상 데이터는 학습 데이터에서 분리 (수정/유지 선택지 미정)
- **5% 임계값 자체** 및 알림 트리거 조건은 probe 후 확정
- **이상치 비율 산출 단위** (전체 행 대비 / 컬럼별 / 일자별) 미정

### 3.3 데이터 누수 방지 원칙 ✅ 확정

> 근거: `00_ml_guide_reference.md` PART 5-1, PART 1-0-2

1. **전처리(스케일링, 결측 대치)는 `Pipeline` 안에서** 수행 → fold마다 train에서만 fit
2. **n8n 전처리 단계**: 통계 계산에 사용하는 구간은 반드시 현재 배치 이전 데이터로 한정
3. 스케일링은 LightGBM/트리 모델에서 **불필요** (단조 변환 불변) — AutoML 파이프라인 외부에서 미리 스케일링하지 말 것

spec `ml_pipeline.md` §6에 "누수 방지: 전처리 통계는 train 구간에서만 계산" 한 줄 추가 대상.

### 3.4 probe 후 spec 역반영 대상

- `feature_spec.md` §4.6 데이터 품질 처리 표(처리 분기·알림 트리거)

## 6. 재학습 후 모델 교체·배포 승인 기준 — 미정

> "교체 기준"(새 모델 vs 기존 모델 비교 후 어느 시점에 바꿀까)과 "배포 승인 기준"(자동/수동·승인 권한·롤백)은 같은 결정 사슬이므로 본 §6에서 통합 결정한다. 결정 후 `docs/spec/08_ai/ml_pipeline.md` §10 미확정 안내에서 "배포 승인 기준" 제거 + spec 본문에 정책 반영.

조사 필요:

- 자동 교체 vs 수동 검토 후 교체
- 점진적 배포 여부(카나리·A/B 테스트)
- 롤백 절차 및 트리거 조건
- 모델 버전 보존 정책 (→ §7 모델 버전 관리와 연계)
