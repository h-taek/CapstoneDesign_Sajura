# ML 파이프라인 설계서

## 1. 파이프라인 목적

수요예측과 추천발주를 사용자 요청 전에 사전 생성하여 DB에 저장하고, 사용자 요청 시 즉시 반환할 수 있도록 한다.

## 2. 실행 방식

- n8n 기반 야간 배치 자동화 파이프라인을 사용한다.
- 매일 02:00 자동 실행한다.
- 주간 단위 정기 재학습을 수행한다.
- 학습 데이터 사용 방식(슬라이딩 윈도우 적용 여부·창 크기 등)은 별도 확정 예정.

## 3. 파이프라인 단계

```text
수집(POS API)
→ 전처리(결측·이상치 검증·표준화)
→ 학습(주간 재학습, 모델은 research §2 확정)
→ 예측(내일 발주량 계산)
→ 캐싱(DB 저장, 즉시 응답 대비)
→ 알림(앱 내 알림)
```

## 4. 입력 데이터

| 데이터 | 출처 | 분류 |
|---|---|---|
| POS 판매 데이터 | POS 연동(CSV 또는 API) | MVP |
| 날씨 단기예보 | 기상청 단기예보 API (data.go.kr) | MVP |
| 과거 기상 데이터 (학습용) | 기상자료개방포털 (data.kma.go.kr) | MVP |
| 시간 정보 | 시스템 | MVP |
| 공휴일 캘린더 | 한국천문연구원 특일정보 API (data.go.kr) | MVP |
| 학사일정 | 홍익대 세종캠퍼스 학사일력 (HTML 파싱) | MVP |
| 유동인구 데이터 (월 단위) | 세종시 행정동별 월간 생활·유동인구 리포트 (세담터 시간대별 미제공 — 37차 대체) | MVP |
| 상권 상가정보 | 소상공인시장진흥공단 상가(상권)정보 (CSV, 분기 갱신) | MVP |
| 레시피 / 폐기 / 점주 수정 이력 | DB | MVP |
| 배달상권 데이터 | 소상공인 배달상권 (SHP, 연 1회) | MVP (선택) |
| 방문인구 (SK 지오비전) | puzzle.geovision.co.kr (유료) | [2단계] |
| 경제지표 | 한국은행 ECOS API | [2단계] |
| 검색량 | 네이버 데이터랩 (유료) | [2단계] |

> 외부 데이터 소스 조사 근거: `docs/research/ai/03_external_data_sources.md` (2026-05-24, 세종 조치원 홍익대 상권 기준).
> 서울 생활인구 API(data.seoul.go.kr)는 세종 미커버 — 본 spec에서 제외.
> **수집 경로 구분(37차)**: 표의 API 경로는 운영 배치(n8n) 기준. 모델링(학습) 단계는 오프라인 수집을 사용한다 — 과거 기상=기상자료개방포털 다운로드 CSV, 공휴일=`holidays` 패키지 생성, 학사일정=수동 정리 CSV. 상세: PROGRESS §3 "AI 학습 데이터 수집 경로".

## 5. 최소 데이터 스키마

- 날짜/시간
- 매장 ID
- 메뉴 ID
- 판매 수량
- 식자재 ID
- 레시피 소모량
- 현재 재고
- 리드타임
- 날씨/기온/강수
- 공휴일/요일
- 이벤트 여부
- 학사일정 (학기·방학·시험기간)
- 유동인구 (월 단위 — 일별 조인 시 전월 lag 값 사용)

## 6. 전처리

- POS별 원본 데이터를 어댑터로 수집한다.
- Canonical Schema로 변환한다.
- JSON Schema 또는 Pydantic으로 형식을 검증한다.
- 결측, 이상치, 표준화를 처리한다.
- 이상치 탐지: IQR 우선 (왜도 높은 분포), Z-score 보조 (정규 분포). 임계값은 별도 확정 예정.
- 결측값 처리: 판매량 forward-fill, 날씨 선형 보간 등 컬럼별 전략. 상세는 별도 확정 예정.
- **누수 방지**: 보간·통계 계산에 사용하는 기준값은 현재 배치 이전 train 구간 데이터에서만 산출한다.

## 7. 학습

- 초기 AI 모델은 미확정 (베이스라인 비교 후보 중 선정).
- 주간 단위 정기 재학습을 수행한다.
- 판매 결과와 폐기 데이터를 반영한다.
- 점주 수정 이력을 재학습에 반영한다.

## 8. 예측

- 메뉴별 1-3일 예상 수요를 예측한다.
- 예측 결과를 DB에 저장한다.
- 추천발주안을 사전 생성하여 DB에 저장한다.
- 저장된 결과가 있으면 사용자 요청 시 DB에서 즉시 반환한다.
- 저장된 결과가 없으면 AI Server를 직접 호출하고 결과를 저장한다.

## 9. 예측 근거 생성

- 예측 결과와 함께 점주가 이해할 수 있는 근거를 생성한다.
- 산출 방법·출력 형태는 별도 확정 예정.
- 예측 신뢰도가 낮으면 경고 배지를 함께 표시한다.

## 10. 운영 및 모니터링

- `pipeline_jobs` 테이블로 파이프라인 실행 상태를 추적한다.
- 실패·지연 시 Slack 알림을 제공한다.
- GitHub Actions를 통해 CI/CD 자동화를 적용한다.
