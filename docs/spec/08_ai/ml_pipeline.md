# ML 파이프라인 설계서

## 1. 파이프라인 목적

수요예측과 추천발주를 사용자 요청 전에 사전 생성하여 DB에 저장하고, 사용자 요청 시 즉시 반환할 수 있도록 한다.

## 2. 실행 방식

- n8n 기반 야간 배치 자동화 파이프라인을 사용한다.
- 매일 02:00 자동 실행한다.
- 주간 단위 정기 재학습을 수행한다.
- 학습 데이터는 최근 N개월만 사용하는 슬라이딩 윈도우 방식을 적용한다.

## 3. 파이프라인 단계

```text
수집(POS API)
→ 전처리(결측·이상치 검증·표준화)
→ 학습(LightGBM, 주간 재학습)
→ 예측(내일 발주량 계산)
→ 캐싱(DB 저장, 즉시 응답 대비)
→ 알림(점주에게 푸시 발송)
```

## 4. 입력 데이터

| 데이터 | 출처 |
|---|---|
| POS 판매 데이터 | POS 연동(CSV 또는 API) |
| 날씨 데이터 | 기상청 AWS API |
| 시간 정보 | 시스템 |
| 캘린더/특수일 정보 | 공공 캘린더 |
| 서울시 유동인구 데이터 | 서울시 공공데이터 |
| 레시피 | DB |
| 폐기 데이터 | DB |
| 점주 수정 이력 | DB |

> 추가 외부 데이터 후보(경제지표·검색량·SNS 노출도)는 조사 중. `docs/research/ai/02_ml_pipeline_open_items.md` §1 참조.

## 5. 최소 데이터 스키마

- 날짜/시간
- 매장 ID
- 메뉴 ID
- 판매 수량
- 식자재 ID
- 레시피 소모량
- 현재 재고
- 리드타임
- 날씨/기온/강수
- 공휴일/요일
- 이벤트 여부

## 6. 전처리

- POS별 원본 데이터를 어댑터로 수집한다.
- Canonical Schema로 변환한다.
- JSON Schema 또는 Pydantic으로 형식을 검증한다.
- 결측, 이상치, 표준화를 처리한다.
- IQR 및 Z-score 기반으로 이상치를 탐지한다.
- 이상 데이터는 학습 데이터에서 분리한다.

## 7. 학습

- LightGBM을 초기 AI 모델로 사용한다.
- XGBoost/LightGBM은 baseline 3단계에 해당한다.
- 주간 단위 정기 재학습을 수행한다.
- 판매 결과와 폐기 데이터를 반영한다.
- 점주 수정 이력을 재학습에 반영한다.

## 8. 예측

- 메뉴별 1-3일 예상 수요를 예측한다.
- 예측 결과를 DB에 저장한다.
- 추천발주안을 사전 생성하여 DB에 저장한다.
- 저장된 결과가 있으면 사용자 요청 시 DB에서 즉시 반환한다.
- 저장된 결과가 없으면 AI Server를 직접 호출하고 결과를 저장한다.

## 9. XAI 생성

- LightGBM Feature Importance로 전역 영향도를 생성한다.
- SHAP으로 개별 예측 결과의 피처 기여도를 산출한다.
- 주요 영향 변수 Top-3를 자연어로 변환한다.
- 예측 신뢰도가 낮으면 경고 배지를 함께 표시한다.

## 10. 운영 및 모니터링

- n8n 실행 결과 모니터링 대시보드를 제공한다.

- GitHub Actions를 통해 CI/CD 자동화를 적용한다.
