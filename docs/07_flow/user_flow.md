# 사용자 흐름 설계서

## 1. 주요 사용자

- 오프라인 식음료 매장 운영자
- 음식점 및 카페 소상공인
- 식자재 재고 관리에 어려움을 겪는 자영업자
- 데이터 기반 경영을 원하지만 IT 역량이 부족한 사용자

## 2. 핵심 사용 흐름

```text
회원가입/로그인
→ 매장 정보 입력
→ 초기 재고 입력
→ 초기 메뉴 입력
→ POS 연동
→ 메인 대시보드
→ 수요예측 확인
→ 추천발주 확인
→ 점주 수정/승인
→ 쿠팡 장바구니 자동 담기
→ 쿠팡에서 결제 진행
```

## 3. 온보딩 흐름

1. 사용자가 Google 또는 카카오 로그인을 선택한다.
2. 인증을 완료한다.
3. 매장명, 업종, 연락처를 입력한다.
4. 초기 재고를 입력한다.
5. 초기 메뉴를 입력한다.
6. POS 연동 정보를 입력한다.
7. POS 연동 성공 시 메인 화면으로 이동한다.
8. POS 연동 실패 시 재시도를 요청받는다.

## 4. 일일 운영 흐름

1. 점주가 메인 대시보드에 접속한다.
2. 시스템이 저장된 예측 결과와 추천발주안을 조회한다.
3. 점주가 메뉴별 예상 수요를 확인한다.
4. 점주가 품목별 권장 발주 수량과 예상 소진 시점을 확인한다.
5. 점주가 추천 근거와 예측 신뢰도를 확인한다.
6. 점주가 발주 수량 또는 상품을 수정할 수 있다.
7. 점주가 발주를 확정한다.
8. 시스템이 쿠팡 장바구니 자동 담기를 수행한다.
9. 점주는 쿠팡에서 실제 결제를 진행한다.

## 5. 재고 관리 흐름

1. 점주가 재고 관리 화면에 진입한다.
2. 재고 목록을 확인한다.
3. 필요한 경우 재고를 등록 또는 수정한다.
4. 폐기할 식자재가 있으면 폐기 요청을 입력한다.
5. 시스템이 폐기 가능 수량을 검증한다.
6. 폐기 가능 시 재고를 차감한다.
7. 폐기 불가 시 오류를 표시한다.

## 6. 메뉴 관리 흐름

1. 점주가 메뉴 관리 화면에 진입한다.
2. 메뉴 목록을 확인한다.
3. 메뉴를 등록, 수정, 삭제한다.
4. 메뉴 등록 시 메뉴명 중복을 확인한다.
5. 레시피가 있으면 메뉴와 함께 저장한다.

## 7. 판매 데이터 조회 흐름

1. 점주가 판매 데이터 조회 화면에 진입한다.
2. 조회 기간을 선택한다.
3. 판매 목록을 확인한다.
4. 특정 판매 데이터를 선택해 상세 정보를 확인한다.

## 8. 사용자 통제 흐름

- AI는 추천만 수행한다.
- 점주는 발주 전 추천안을 확인한다.
- 점주는 추천안을 수정할 수 있다.
- 최종 발주 확정은 점주의 명시적 승인으로 수행한다.
- 자동 발주 추천은 자동 결제가 아니다.

## 추가 작업 필요 항목

- 실제 화면 IA 정의 필요
- 모바일 PWA 화면별 동선 정의 필요
- 알림톡/앱 푸시/SMS 중 실제 알림 채널 확정 필요
- 온보딩 진행률 표시 상세 UX 정의 필요
- 예측 신뢰도 경고 배지 표시 위치 정의 필요
